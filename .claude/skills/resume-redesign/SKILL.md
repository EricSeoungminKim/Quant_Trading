## 1. 이 프로젝트에서 반복해서 참인 것

이번 재설계에서 찾은 결함 대부분이 같은 모양이었다. **먼저 의심할 것:**

| 패턴 | 실제 사례 |
|---|---|
| 상류가 사라졌는데 하류 조건이 남음 | Claude 브리핑 세션이 없어졌는데 `today_articles > 0` 이 그대로 → "기사 있음"이 "개장 매수"가 됐다 |
| 방향 없는 크기 | 하락률 보드가 상승률과 같은 가점 → 폭락 종목이 매수 후보 |
| 문서에만 있는 규칙 | `strategies/CLAUDE.md` 가 금지한 import 가 실제로 존재했다 |
| "모른다"를 "이상 없음"으로 | 캐시 실패 시 0 을 돌려주면 "중복이니 건너뜀"으로 읽혀 데이터가 사라진다 |
| 적용했다고 믿기 | Redis `maxmemory` 가 실제로는 반영 안 된 채 무제한으로 돌았다 |

## 2. 작업 방식 (Phase 하나당)

1. **먼저 측정한다.** 키워드·임계·가중치를 지어내지 말고 실제 데이터에 돌려본다.
   MySQL 에 뉴스·체결·선정이 있다:
   ```bash
   ssh ubuntu@100.87.129.113 'cd ~/quant_trading_kiwoom && set -a && . ./.env.local && set +a && \
     MYSQL_PWD=$MYSQL_PASSWORD mysql --default-character-set=utf8mb4 -h127.0.0.1 -u$MYSQL_USER $MYSQL_DATABASE'
   ```
   뉴스 방향 규칙은 이렇게 1,425건에 돌려 종목 단위 7% 로 조정했다. 감으로 정한
   숫자는 나중에 옳았는지 알 방법이 없다.
2. **테스트 먼저.** 실패를 확인한 뒤 구현한다. 테스트 문구에 *왜* 를 적는다.
3. **구현.** 기존 스타일을 따른다. 주석은 '무엇'이 아니라 '왜'.
4. **검증.** `uv run pytest` + 해당 스모크. **실환경에서 한 번 더 돌려본다** —
   가짜 연결 테스트가 통과했는데 실 MySQL 에서 `IntegrityError` 로 죽은 적이 있다.
5. **커밋.** 무엇이 아니라 **왜**를 쓴다. 실측값을 넣는다.
6. **기록.** `docs/vault/변경기록.md` 맨 위에 항목 추가. 계획 파일 체크박스 갱신.

## 3. 절대 하지 말 것

- **거래 평면에 네트워크·DB·Redis 를 넣지 않는다.** `tests/test_architecture.py`
  가 막는다. 막히면 우회하지 말고 설계를 고쳐라.
- **`KNOWN_DEBT` 에 새 항목을 추가하지 않는다.** 그 목록은 줄어들기만 한다.
- **테스트를 약화시켜 통과시키지 않는다.**
- **EC2 배포는 장 마감 후.** KR 15:30 / US 06:00 (KST) 이후. 포지션이 없는지
  먼저 확인하고, 엔진을 멈춘 뒤 배포한다(돌아가는 프로세스 밑에서 파일을 바꾸면
  지연 임포트가 깨진다).
- **비밀번호를 화면에 찍지 않는다.** 서버에서 생성해 `.env.local`(600)에 직접 쓴다.
