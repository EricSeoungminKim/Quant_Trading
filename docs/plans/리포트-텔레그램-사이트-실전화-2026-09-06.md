# 리포트·텔레그램·사이트 실전화 계획 (2026-09-06 저녁, 소유자 지시)

지시: "매일 리포트의 상승/하락 판단과 언급 종목의 점수·호재성이 실제 결과와 맞았는지 **과거 리포트를
날짜별로 하나씩** 보며 확인하고 보완하라. 리포트·텔레그램·사이트는 전략만 찾으면 바로 실전 계좌로
가도 되는 품질이어야 한다. 한 번에 다 하지 말고 계획대로 단계별로."

원칙: 단계마다 **근거 문서 + 테스트 + 배포 확인**이 있어야 다음 단계로 간다. 한 단계 = 워커 1개.
9/6 통계 감사(`quant/control/report_accuracy.py`, 59개 리포트)는 집계였고, 이 계획은 날짜별 회고다.

| 단계 | 내용 | 산출물 | 상태 |
|---|---|---|---|
| 1 | **날짜별 회고 감사** — 08-13 이후 모든 KR/US 아침·마감 리포트를 하루씩: 그날 리포트가 말한 것(스탠스, 섹터, 언급 종목·점수·호재 태그) vs 실제(지수 등락, 종목 D+0/D+1, 그날 실제 상위 등락 종목 중 리포트가 놓친 것) | `results/report_review/YYYY-MM-DD_{KR,US}.md` 회고 카드 + 종합표 + 체계적 오류 목록 | ⏳ |
| 2 | **점수·예측·화제성 개선** — 1단계 근거로 스탠스 규칙 재보정(또는 강등), 종목 점수 가중 재조정, 놓친 급등주를 잡을 특징(수급·거래대금·뉴스 밀도·섹터 모멘텀) 추가를 리포트 자체 이력으로 rank IC 검증 후 반영 | quant/analyze 변경 + 테스트 + 반영 전/후 IC 표 | ⏹ |
| 3 | **리포트 실전 품질** — 섹션별 QA 체크리스트, "리포트 린트"(NaN·모순·미기록 주장·낡은 문구 금지), 픽스처 렌더 테스트, 텔레그램 요약 일치 | quant/report/lint.py + 빌드 게이트 | ⏹ |
| 4 | **텔레그램 실전 품질** — 발송 카탈로그(모든 발신 → 레인·형식·이스케이프·중복·빈도), 실패 처리, 메시지 계약 테스트, 킬스위치 드릴 절차 | docs/runbooks/telegram-catalog.md + 테스트 | ⏹ |
| 5 | **사이트 실전 품질** — 월요일 첫 에폭 발행 검증, performance.json ↔ 스코어보드 교차 대조, 접근성·성능 점검, "읽는 법" 페이지 | 교차 대조 테스트 + 사이트 커밋 | ⏹ |
| 6 | **재발 방지 루프** — 1단계 회고 카드를 매일 자동 생성(06:40 정확도 크론에 통합), 주간 리뷰 텔레그램 | 크론 + 브리핑 레인 | ⏹ |

진행 기록은 `docs/vault/변경기록.md`, 판정은 `docs/runbooks/live-readiness.md` F 절에 반영한다.
