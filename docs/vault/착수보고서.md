# 착수 보고서 — 자동 리포트→검증→매매→수익 루프

> **이 문서의 용도**: 이 프로젝트의 시작과 끝을 한 파일에 담는다. **다른 Claude
> 세션·계정이 이 문서 하나만 읽고 이어서 일할 수 있어야 한다.** 작업이 끝나거나
> 추가될 때마다 여기를 고친다.
>
> **읽는 순서**: §1 무엇을 만드는가 → §2 시스템 지도 → §3 원칙(왜 이렇게 하는가)
> → §5 현황(무엇이 끝났고 뭐가 남았나) → 부록.
>
> **작업을 시작하기 전에**: §3 원칙을 반드시 읽는다. 여기 적힌 실패들은 전부
> 실제로 났던 것이고, 원칙은 그 대가로 얻은 것이다. 원칙을 모르면 같은 실패를
> 다시 만든다.

## 1. 무엇을 만드는가

사용자(개인 투자자, 실계좌 운용)가 원하는 최종 형태:

```
자동 리포트  →  검증  →  주식매매  →  수익  →  파라미터 조정
    ↑                                              │
    └──────────────────────────────────────────────┘
```

- **리포트**: 매일 개장 전, 그날 살 만한 종목을 근거와 함께 뽑는다 (KR 08:00 / US 20:00)
- **검증**: 결정론적 확신도 엔진이 후보를 채점해 통과분만 관심종목에 넣는다
- **매매**: 전략들이 실시간 시세로 진입·청산한다
- **수익**: 체결이 원장에 쌓이고 세션별 손익이 금액으로 보고된다
- **되먹임**: 어떤 속성의 종목이 실제로 돈이 됐는지 측정해 파라미터를 조정한다

**앞의 넷은 2026-08-13에 실제로 한 바퀴 돌았다.** 없는 것은 마지막 화살표다.

### "완성"의 정의

아래 5개가 전부 참일 때 완성으로 본다. 지금은 1번만 참이다.

| # | 조건 | 상태 |
|---|---|---|
| 1 | 사람 개입 없이 리포트→편입→매매→손익보고가 매일 돈다 | ✅ 2026-08-13 달성 |
| 2 | 선정 근거와 결과가 매일 자동으로 원장에 쌓인다 | 🔨 진행 중 |
| 3 | 어떤 근거가 돈이 됐는지 숫자로 답할 수 있다 (종결 30건+) | ⬜ |
| 4 | 하네스가 파라미터를 제안하고 거버너가 안전하게 반영한다 | 🔨 거버너 완료, 하네스 미착수 |
| 5 | 최소 한 전략이 `burn_in` → `verified` 로 승격됐다 | ⬜ |

## 3. 원칙 — 전부 실제 실패에서 나왔다

### 원칙 1. 모르는 것을 아는 척하지 않는다

가장 비싼 버그들이 전부 여기서 나왔다.

- `parse_published`가 타임존 없는 시각을 **UTC로 우겼다** → 매일경제·인포스탁데일리
  기사가 9시간 젊게 찍혀, 낡은 기사가 "방금 나온 것"으로 시간 창을 통과했다.
- 죽은 피드(HTTP 200, 562일 전 정지)를 **0건으로 받아 정상처럼** 넘겼다.
- `relative_volume`을 계산 못 했을 때 0으로 채웠다면 "거래량 없음"과 구분이 안 됐다.

→ **결측은 값이다.** `None`을 돌려주고, 호출부가 그것을 **센다**. 조용히 틀린
값보다 드러난 결측이 낫다.

### 원칙 2. 소스는 "고유 기여도"로 산다

피드 감사 실측: 뉴시스는 100건을 주는데 종목 언급 1%, 구글_반도체는 고유 기여 0.
둘 다 뺐다. **볼륨은 가치가 아니다.**

→ 소스 추가 기준은 하나: *"이 소스만 잡아내는 게 몇 개인가."* 0이면 장애 지점만
하나 느는 것이다.

### 원칙 3. 판단은 LLM, 채점은 코드

하네스를 붙일 때 이 경계가 무너지면 재현이 안 된다. LLM은 **가설만** 낸다.
검증도 반영도 결정론적 코드가 한다. `quant/control/governor.py`가 그 경계다.

관련 불변식: **거래 핫패스에 LLM/네트워크 호출 금지**(ADR-0002). 2026-08-13에
자동 편입 경로에서 LLM이 통째로 빠졌다 — 자체 리포트는 후보를 이미 결정론적으로
계산해 내므로 해석할 산문이 없다.

### 원칙 4. 권한을 실수 비용에 비례시킨다

자동 반영에서 **선정 문턱은 열고 사이징은 잠갔다.**

| 자동 허용 (무엇을 볼 것인가) | 자동 금지 (얼마를 걸 것인가) |
|---|---|
| `min_articles`, `min_streak`, `news_hot` | `capital_fraction` |
| `rank_top`, `trending_min`, `vol_surge_ratio` | `stop_loss_pct`, `risk_budget_pct` |
| | `max_entries_per_session`, `max_leverage` |

선정을 틀리면 하루 놓치고 다음날 되돌리면 끝이다. 사이징을 틀리면 **계좌가
날아가고 되돌릴 자산이 남지 않는다.** 회복 가능성이 다르면 권한도 달라야 한다.

### 원칙 5. 표본이 쌓이기 전에는 성과를 주장하지 않는다

승격 기준: **종결 30건 + 승률 95% 신뢰구간이 50%를 위로 벗어날 것**
(`ledger.MIN_TRIPS_FOR_JUDGEMENT`). 코드가 자동 승격하지 않는다 — 사람이
`evidence`를 채워 `verified`로 올린다(숫자 조작 유인 차단).

## 6. 미결 판단 (근거와 함께)

### 시간외 신호를 EVENT와 합칠 것인가 → **분리한다**

성격이 다르다. 뉴스 호재는 "아직 안 오른 것", 시간외 급등은 "이미 오른 것"이다.
2026-08-13 한화생명은 09:10에 5,560을 찍고 5분 뒤 5,130까지 밀렸다 — 되돌림
위험이 구조적으로 다르다. 합치면 **어느 쪽이 돈이 됐는지 영영 모른다.**
2주 뒤 숫자로 판단한다.

### 보조지표를 언제 넣을 것인가 → **1단계 이후**

지표는 늘리는 만큼 과최적화 위험이 커진다. 측정 없이 넣으면 도박이다.
전방 수익률이 돌기 시작하면 "RSI 게이트가 승률을 올렸나"를 재면서 넣는다.

### 자동 반영을 얼마나 열 것인가 → **선정만, 사이징은 영구 잠금**

§3 원칙 4. `governor.FORBIDDEN`이 강제하고 테스트가 고정한다.
