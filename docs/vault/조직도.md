# 조직도 — 6역할 워크플로우 (소유자 정본, 2026-08-26)

소유자 지시 원문이 이 시스템의 정본 조직도다. **모든 기능 추가·평가는 "이 6역할
중 어디에 속하는가"로 판단한다.** 어느 역할에도 속하지 않는 기능은 의심하라.

> "외부 지표들과 소스들을 잘 정제해서 하나의 우리 프로그램을 위한 데이터가
> 되면서, 프로그램은 그 데이터를 기반으로 정해진 규칙과 시그널에 맞추어 매매만
> 하면 되는 거야. 종목을 제대로 알맞는 전략에 상황에 맞게끔 던져 주고
> 지정해주면, 그 해당 종목을 해당 전략이 watch 하다가 signal 이 오면 거래를
> 시작하는 거지."

## 역할 ↔ 시스템 매핑

### ① 데이터 통합 — "뉴스 종합 + 키움/토스 데이터를 우리 기업 것으로 합치는 사람"

| 소스 | 모듈 | 시각 |
|---|---|---|
| 뉴스(피드 20여 종) | `quant/collect/` + news-collect 타이머 | 30분마다 |
| 토스 거래대금·랭킹 보드 | `toss_rankings` 수집 | 리포트 빌드 시 |
| S&P500 전날 상승 섹터 → KR 대장주 | `quant/analyze/us_kr_bridge.py` + 마감 종합(wrap) | 05:50 |
| DART 공시 | `dart_collect.sh` | 07:20 / 13:25 |
| 네이버 수급·컨센서스·펀더멘털 | `stock_detail` / `naver_fundamentals` | 리포트 시 / 15:45 |
| 외인·기관 수급 원장 | `kr-flow`(마감 후) + 아침 리포트 | 15:50 / 07:30 |
| 1분봉·일봉 | 키움 웹소켓(실시간) + Toss/야후 백필 | 상시 / 05:40 등 |

**공백(정직하게)**: 키움 "각종 상위랭킹"은 아직 미수집 — 현재 랭킹은 토스만.
키움은 실시간 시세 전용이다. 키움 랭킹 소스 추가는 확장 백로그.

### ② 종목 선정 — "회사 규율에 맞게 오늘의 투자/지켜보기 종목 선정"

- 리포트 채점: `watch_scorer`(확신도 엔진, 태그별 증거점수) + `baseline_score`
  + 트렌딩 점수 — 아침 08:00 / 장중 14:50경 / US 20:00.
- 감시 축 합류: 거래량 반복(volume_watch)·전일 세션 패턴(wrap)·점수 연속
  강세(streak) — 전부 선정 원장(`selections.jsonl`)에 근거와 함께 기록.
- **"아무거나 선정하지 않는다"의 강제 장치**: 자동 편입은 전부 확신도
  게이트(watch-score)를 통과해야 하고, 선정 근거는 원장에 남아 outcomes 가
  전방 수익률로 채점한다 — 근거 없는 선정은 구조적으로 불가능하다.
- 수습: AI 트레이더(3역할 토론)가 같은 서류로 독립 선정 판단 — 리더보드가
  기존 선정자(watch_scorer)와 같은 잣대로 채점(승격은 사람).

### ③ 전략 배정 — "선정 종목을 알맞은 전략 트레이더에게 지정"

태그가 배정장이다: 리포트가 `SYM:TAG` 로 발행 → own_brief 가 확신도 게이트
통과분을 워치리스트에 태그와 함께 등록 → 유니버스 롤에서 전략별 배정.

| 태그 | 받는 트레이더 | 의미 |
|---|---|---|
| EVENT | news_momentum | 뉴스 호재(악재 표지 시 태그 안 줌) — 개장 모멘텀 |
| CLOSE_BET | close_bet | 종가배팅 후보(수급·거래대금·마감강도) |
| FRGN / FRGN_EXIT | frgn_accumulate | 외국인 추세 적립 / 이탈 청산 |
| TREND·무태그 | (유니버스 합류) | scalp_1m 등 전 전략이 가격으로 감시 |

배정표의 코드 명시화 + 편입 알림에 배정 표시: 2026-08-26 신설(`TAG_ASSIGNMENT`).

### ④ 트레이더들 — "전략마다 1명, 각자 1,000만원, 그 전략의 고수"

- 전략 4종(활성): news_momentum · scalp_1m · close_bet · frgn_accumulate —
  각자 **독립 명목계정 1,000만원**(`capital_mode: per_strategy`,
  `strategy_books.json`, `cli strategy-pnl` 로 개인 성적).
- **진입 일지**: 체결마다 트레이더의 시그널 기록(reason — 패턴·구조손절 근거·
  게이트/W%R 판정)이 거래 원장(`trades.jsonl`)에 영속화된다(2026-08-26 신설
  — 그전엔 엔진 로그에만 있어 사라졌다). 역할 ⑤의 입력이다.
- 트레이더는 "매매만 한다": 거래 평면은 결정론·네트워크 금지, 뉴스→주문
  직접 경로는 아키텍처 테스트가 코드 수준에서 차단.

### ⑤ 일일 평가·피드백 — "왜 확신도 대비 결과가 나빴나, 전략별 피드백"

| 도구 | 주기 | 답하는 질문 |
|---|---|---|
| **daily-feedback**(2026-08-26 신설) | 매일 KR 16:45 / US 06:25 | 진입 타이밍 피드백 — 고점매수·거래 소강 진입·늦은 진입(소유자 예시를 규칙화). 진입 일지(reason) 인용 |
| outcomes + 리더보드 | 16:00 / 16:20 | 선정 근거 vs 전방 수익률(확신도 채점) |
| forensics(부검) | 금 16:10 | MFE/MAE·청산 효율·진입 위치 대조군 |
| experiments(자동 판정) | 매일 16:30 | 설정 변경 전후 이중차분+순열검정, 전략 사망 경보 |
| weekly-review + param-propose | 토 06:25/06:40 | 주간 종합 + 파라미터 변경 가설(제안만) |

### ⑥ 소식통 관리 — "대표에게 닿는 채널의 배달 확인"

- **delivery-check**(2026-08-26 신설): 매일 06:35(한 바퀴 완료 후) — 그날 4개
  리포트 산출물 존재·발송 흔적 점검, 이상 시에만 알림.
- ops_watch(매시): 시스템 이상(낡은 봉·죽은 피드·시크릿). watchdog(5분):
  엔진 생존. — 이 둘은 "시스템이 도는가", delivery-check 는 "대표에게
  닿았는가"로 관점이 다르다.

## 이 문서의 유지 규칙

역할에 해당하는 기능이 바뀌면 이 표를 같이 고친다(변경기록과 동일 관례).
낡은 조직도는 없는 것보다 나쁘다 — 신입(사람이든 에이전트든)이 이걸 보고
어디에 뭘 넣을지 정하기 때문이다.
