## 우리가 실제로 쓰는 것 / 안 쓰는 것

`daily_brief.sh`는 리포트 **전문을 Claude에 넘기고**, 스킬이 그중에서 종목 후보를
뽑아 `AUTO_WATCH: 심볼:태그:날짜` 한 줄로 돌려준다. 즉 지금은 **17개 섹션 대부분이
LLM 컨텍스트만 차지하고 결과에 기여하지 않는다.**

실제 기여:
- **16·17번(AI 요약)** — 종목 이름과 논지(TREND/REBOUND/EVENT)가 여기서 나온다
- **2·4·10·12·14번** — 국면 맥락 (방어/중립/공격 판단의 배경)

기여 없음(사용자 판단 "필요없는 부분"):
- 7번 일본 국채, 8번 지수 변동 재탕, 1번 한 줄 총평
- 3번 원자재·6번 국고채·13번 P/C·15번 CDS는 우리 전략(일중 돌파·평균회귀)의
  판단 축과 연결점이 없다

## 우리만의 리포트를 만든다면 (설계 메모)

이 저장소는 이미 리포트에 필요한 데이터 대부분을 **직접** 갖고 있다:
- 지수·환율·섹터 → Toss API (`market_indicator`, `rankings`)
- 국면 판단 → `regime/` (US=QQQ, KR=KODEX200+수급) — **남의 총평보다 우리 국면이 정확**
- 종목 채점 → `app/watch_scorer.py` 확신도 엔진 (프리퍼시티 + 논지별 증거점수)
- 수급 → 키움 ka10059 (종목별 외국인·기관)
- 성적 → `app/ledger.py` 스코어보드 (신뢰구간·판정 포함)

즉 우리 리포트의 차별점은 **"시장이 어떻다"가 아니라 "우리 시스템이 오늘 무엇을
왜 할 것인가"**여야 한다. 남이 만든 시황 요약을 다시 쓰는 건 의미가 없다.

제안 골격:
1. **오늘의 국면** — 시장별 방어/중립/공격 + 그 판정의 근거 지표 값
2. **오늘의 유니버스** — 관심종목별 확신도 점수(항목별 득점) + 편입/탈락 사유
3. **어제의 전적** — 전략별 실현/평가 손익 + 누적 스코어보드(신뢰구간·판정)
4. **전략 상태** — burn_in/verified, 승격까지 남은 표본 수
5. **경고** — 시세 끊김, 원장↔현금 불일치, 안전장치 발동 이력
6. (선택) **외부 맥락** — 위 17개 중 ✅ 표시된 것만, 값만 짧게
