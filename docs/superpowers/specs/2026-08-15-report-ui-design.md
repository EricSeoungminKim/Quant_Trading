# 리포트 고도화 (서브프로젝트 B) — 설계 스펙

> 2026-08-15. A(뉴스 심화)·E(채점 루프) 다음. 사용자가 준 리포트 개선 요구 5건을
> 구현한다. A 가 만든 데이터(`relations`, `sector_map`)의 **첫 소비자**다.

## 사용자 요구 → 현재 상태 → 처방

| # | 요구 | 현재 | 처방 |
|---|---|---|---|
| 1 | 종목 뉴스를 탭하면 스크레이핑된 만큼 전부 | 템플릿이 `c.titles[:3]` 으로 자름(데이터는 전부 있다) | 슬라이스 제거 + `<details>` 로 접기 |

| 5 | 뉴스 심화 + 링크만 보관·해시 축소 | **A 에서 완료** (본문 비영속, `link_sha` 색인) | B 에서 추가 작업 없음 — 스펙에 명시만 |

## 핵심 결정 1 — 호스팅: jinja2 유지 (Next.js/Vercel 기각)

사용자가 "웹 호스팅 전환을 고려해도 된다"고 했으나 **기각한다**:

- 요구 1~4 의 상호작용은 전부 `<details>`/CSS 로 된다. JS 프레임워크가 필요한
  기능이 하나도 없다.
- Vercel 은 **공개 호스팅**이다. 지금 리포트는 Tailscale 인터페이스에만 바인딩되고
  `robots.txt` 전면 Disallow 다. 포지션·후보 종목이 실린 산출물을 공개망에 올리는
  것은 인증을 붙이기 전엔 위험하고, 인증을 붙이면 복잡도가 급증한다.
- 현재 차트는 **서버사이드 SVG** 라 "같은 스냅샷 = 같은 바이트"가 성립한다.
  클라이언트 렌더로 바꾸면 이 결정론이 깨진다.
- ADR-0002(웹 프레임워크 없음)를 뒤집을 근거가 이 요구들에는 없다.

**다시 검토할 조건**: 실시간 필터·정렬·검색처럼 `<details>` 로 안 되는 상호작용이
요구되거나, 외부 공유가 필요해질 때. 그때는 빌드 없는 vanilla JS 소량부터 시작한다.

## 핵심 결정 2 — 수급 기간 뷰는 "긁기"가 아니라 "축적"

1년치를 외부에서 긁으면 종목당 20페이지 × 종목 수의 요청이 필요하다(토스는 주문
집행과 같은 경로라 요청을 늘리면 안 되고, 네이버도 예절 문제다).

대신 **매일 스냅샷을 원장에 적재**한다:

- 리포트 빌드가 이미 받아오는 종목별 수급(네이버 10일)을 `data/ledger/flows.jsonl`
  에 날짜·종목 단위로 append(멱등 — 같은 날짜·종목은 갱신).
- 표시 기간은 **축적된 만큼**: 1일/5일/10일은 오늘부터 즉시(네이버가 10일을 준다),
  1개월/3개월/6개월/1년은 쌓이는 대로 열린다.
- **없는 기간을 0으로 그리지 않는다** — "N일치 축적됨(YYYY-MM-DD 부터)"을 함께
  적는다. 이 저장소의 `unknown` 1급 원칙.

이게 사용자의 "빅데이터를 모은다" 방향과도 일치한다 — 남의 화면을 긁는 대신
우리 원장을 만든다.

## 보안 — LLM 출력이 HTML 에 들어간다

`relations[].reason` 은 기사 본문을 읽은 LLM 이 만든 문자열이다. 지금까지는 HTML
경로에 없어서 무해했지만 B 가 처음으로 화면에 올린다.

- jinja2 `autoescape` 가 켜져 있다(`render.py`) — 그대로 두고 **`|safe` 를 절대
  쓰지 않는다**.
- `parse_candidates` 가 이미 `<`·`>` 를 제거한다(A 의 최종 수정) — 이중 방어.
- 테스트로 고정한다: reason 에 `<script>` 가 들어와도 렌더 결과에 실행 가능한
  태그가 없다.

## 실패 모드

| 실패 | 동작 |
|---|---|
| 업종 등락률 페이지 실패 | 섹터 섹션은 `sector_map` 만으로 그리고 등락률 칸은 "미확인"(0% 아님) |
| `relations` 아티팩트 없음 | 수혜주 트리 섹션 자체를 그리지 않는다(빈 트리 금지) |

## 검증

- 순수 조립·파서는 실 HTML 조각 픽스처 단위 테스트
- 템플릿 렌더 결과를 문자열로 검증(뉴스 개수·트리 존재·escape)
- 로컬 E2E: `report_cli build --market KR` 후 산출 HTML 에서 **직접 센다** —
  종목당 뉴스 개수, 수혜주 트리 종목 수, 섹터 수, 수급 기간 표기
- `uv run pytest` 전체 + 아키텍처 테스트(KNOWN_DEBT 증가 0)
