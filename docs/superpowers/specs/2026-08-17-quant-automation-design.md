# 3갈래 퀀트 트레이딩 자동화 (서브프로젝트 T) — 설계 스펙

> 2026-08-17 사용자 방향: "리포트만 구현했다면, 이제 모아온 정보 기반으로 퀀트
> 트레이딩을 상시 가동 — 시그널 감지 → 종목 선정 → 진입의 전체 자동화."
> **돈이 걸린 거래 평면** — 이 스펙은 설계+승격 게이트를 정의하고, 구현 착수 전
> 사용자 결정(§5)을 받는다.

## 자본 3갈래 (사용자 정의)

| 갈래 | 내용 | 상태 |
|---|---|---|
| **A. 단타 자동** | 당일 뉴스·호재 기반 — intraday_scorer v4 선정을 자동매매로 | 신규 배선 |
| **B. 외국인 적립** | 외국인 추세(매수 시그널 라벨) 종목을 주기 매수, 이탈 시 분할 청산 | 신규 전략 |
| **C. 상시 퀀트** | 기존 3전략(donchian·orb·intraday_scan) | 이미 paper 가동 |

## 아키텍처 (기존 불변식 위에)

- **A 배선**: intraday engine json → own_brief 패턴의 게이트 → watch-score →
  유니버스 → 기존 EVENT 계열 전략이 진입. **뉴스→주문 직결 금지 불변식 유지** —
  선정은 유니버스 편집일 뿐, 진입은 전략이 가격으로 판단(기존 원칙 그대로).
- **B 신규 전략**: `quant/trade/strategy/frgn_accumulate.py` — 입력은 유니버스 +
  일봉(결정론), 외국인 라벨은 **유니버스 태그로만** 전달(전략이 collect/analyze
  임포트 금지 — 아키텍처 테스트가 강제). 저빈도(일 1회 판단) 1주/고정액 매수,
  이탈 태그 시 분할 청산. settings.yaml 블록 + STRATEGY_REGISTRY 등록.
- **안전장치**: 기존 방어선(킬스위치·회로차단기·잔고대조·워치독) 그대로 적용.
  신규 갈래는 **paper 모드에서 시작**, 갈래별 자본 상한 별도.

## 승격 게이트 (숫자가 자본을 배분한다 — 자동 승격 없음, 판정만 자동)

- A: intraday_verify(아침 v4 + 오후 v4_close) **n≥30 & 수수료 후 평균 bp>0**
  유지 시 "승격 판정 가능" 알림 → 사용자 결정.
- B: paper 원장 20거래일 & 낙폭·회전율 리포트 → 사용자 결정.
- 판정 리포트는 주간 스코어보드에 갈래별로 편입.

## 비목표
- 즉시 실계좌 투입(전 갈래 paper 시작), 리버리지 확대, 승격의 자동 실행.

## §5 사용자 결정 (확정, 2026-08-17)

1. **갈래별 자본 배분: A 20% / B 30% / C 50%.** `config/settings.yaml`의
   per-strategy `capital_fraction`(시장별 dict)으로 표현 — 새 최상위 배분
   개념을 만들지 않았다. A/B는 KR 전용(데이터 소스가 한국 종목만 다룬다)이라
   US 예산은 그대로 두고, **KR만** 갈래 C(기존 7전략)의 기존 비중을 균등
   x0.5로 눌러 A(0.2)+B(0.3)에 내줬다(settings.yaml 상단 "3갈래 자본 배분"
   표 참고).
2. **A의 진입 전략: 신규 전략**(`quant/trade/strategy/news_scalp.py`) —
   기존 news_momentum(부분익절 사다리)을 재사용하지 않고, 개장 진입·당일
   청산을 고정 규칙으로 못박는다(손절 + EoD 강제청산 둘 뿐, 백테스트가
   측정한 개장가→마감가 방식 그대로 — `quant/backtest/intraday_verify.py`
   참고).
3. **B의 매수 단위: 고정액(100,000 KRW)씩.** 종목 가격이 제각각인
   관심종목에서 1주씩 사면 노출 규모가 종목마다 크게 벌어지므로, 고정액이
   균등 노출을 보장한다(`quant/trade/strategy/frgn_accumulate.py`).
4. **paper 기간: 승격 판정 최소 A 10거래일 / B 20거래일.** 실제 판정식(더
   보수적으로 표본을 요구)은 `quant/control/ledger.py`의
   `news_scalp_promotion_verdict`(intraday_verify 종목-일 n≥30 & 수수료 후
   평균 bp>0)/`frgn_accumulate_promotion_verdict`(paper 원장 거래일≥20)가
   구현한다 — 이 함수들은 **판정만** 반환하고 자동으로 승격(capital_fraction
   변경/enabled 전환)하지 않는다.

**추후 원칙(재배분):** 승격 게이트를 넘긴 뒤에는 이 20/30/50 배분을 고정값이
아니라 시작점으로 본다 — 종결 표본이 쌓이면 스코어보드(`run scoreboard`,
`quant/control/ledger.py`)의 실측 성과를 근거로 재배분한다: 잘 버는 갈래에
지분을 늘리고, 자주 잃는 갈래에서는 줄인다. 사람이 판단하고 사람이 config를
고친다 — 코드가 자동으로 배분을 옮기지 않는다(이 저장소의 검증 게이트와
동일한 "숫자가 자본을 배분한다, 그러나 자동 적용은 없다" 원칙).
