# 뉴스 수집 고도화 (서브프로젝트 H-2) — 설계 스펙

> 2026-08-16. 외부 리서치 기반(상세: 세션 스크래치 news-research.md, 요지는 아래).
> 사용자 요구: "더 많은 뉴스를 과부하 없이 + 다른 회사들 방식을 웹서치로 배워서".

## 리서치가 바꾼 방향 (중요)

- **네이버 뉴스·종목뉴스·공시 페이지는 robots.txt 전면 비허용**(curl 실측 —
  네이버 자체 검색봇 yeti 에게도 `/news/`·`/item/news_*` 미허용. `/sise/`·
  `/research/` 는 yeti 허용 구역). → **뉴스 확장을 네이버 스크레이핑으로 하지
  않는다.** 기존 /sise/ 류 일 1회 소량 크롤은 유지하되 뉴스는 다른 경로로.
- 토스증권 '실시간 이슈'의 실전 패턴: **발행량 급증으로 사건을 먼저 감지 →
  종목을 사후 연결**하는 2단 구조 — 우리 방향과 일치.

## 구성요소 (전부 공식/허용 경로, 추가 부하 최소)

1. **DART OpenAPI 공시 수집** (공식·무료) — 배당·잠정실적·유증 등 **팩트 이벤트**.
   뉴스보다 정확하고 robots 리스크 0. ⚠️ **사용자 액션: DART API 키 무료 발급**
   (`.env.local` 에 `DART_API_KEY`). 수집기는 collect 평면, 일 배치.
2. **후보 종목별 구글뉴스 검색 RSS** — feeds.py 가 이미 쓰는 방식(검색피드 3개)의
   확장: 유니버스 후보 상위 N 종목에 대해 `종목명` 질의 RSS 를 동적으로 추가.
   RSS 라 조건부 GET 가능, 종목-뉴스 매핑이 질의에서 공짜로 나온다.
3. **RSS 조건부 GET**(ETag/Last-Modified) — 기존 33피드 30분 주기의 재전송 비용
   절감. collector 에 캐시 헤더 저장.
4. **제목 MinHash/shingle 클러스터링** — 같은 사건 다매체 기사를 사건 단위로 묶고,
   **클러스터 크기 = 뉴스 모멘텀**(발행량 급증 감지)을 공짜로 얻는다. 순수 함수
   (analyze), 신규 의존성은 표준 라이브러리로 시작(shingle+자카드; datasketch 는
   필요 시).
5. **증권사 리포트 목록**(`finance.naver.com/research/` — yeti 허용 구역) 일 1회 —
   "오늘 리포트가 나온 종목" 이벤트. PDF 본문은 안 읽는다(목록·제목·목표가만).
6. **뉴스 z-score 피처** — 종목별 일 뉴스 건수의 이동 z-score 를 selections 속성에
   추가(E 의 input_hash 에 자연 편입 → 리더보드가 유용성을 채점). 산식 변경이므로
   **producer_version 승급 규율** 적용.

## 비목표
- 네이버 뉴스/종목뉴스/공시 페이지 폴링(robots), NER 모델·온톨로지 풀 구축,
  뉴스 방향(호재/악재)을 거래 진입에 직접 연결(analyze↛trade 불변식),
  Selenium/브라우저 자동화(전부 정적 HTML/RSS/API 로 충분).

## 순서
H-1(네이버 패리티 화면) 완료 후. G(매일 발송)와 독립 — 병행 가능.
1→3→4→6 은 키 불필요라 먼저, 2 는 피드 수 증가라 EC2 부하 측정 후 단계 도입,
5 는 소형. DART(1)는 사용자 키 발급 대기.
