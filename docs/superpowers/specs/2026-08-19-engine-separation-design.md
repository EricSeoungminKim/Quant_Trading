# 엔진 분리 설계 — 전략·리포트를 갈아끼워도 워크플로우가 안 흔들리게

**작성 2026-08-19 (KR 장중, 착수는 마감 후 배포 기준)**

## 왜

소유자 요구: *"각 기능을 엔진이라고 보고, 바꾸고 싶은 것을 바꿀 때 다른 것에
영향이 별로 없게. 전략을 초기화해서 새것으로 바꿔도 기존 워크플로우가 정상
진행되면 좋겠다. 리포트도 똑같이 — 수정할 때마다 전체를 뜯는 게 아니라 고쳐야
하는 부분만 고치게."*

**워크플로우 자체는 바꾸지 않는다.** 경계만 긋는다.

## 지금 상태 (실측 2026-08-19)

| 항목 | 값 | 의미 |
|---|---|---|
| `apps/report_cli.py` | 2,472줄 / 임포트 53개 (analyze 33 · collect 14 · adapters 13) | 모든 평면을 직접 쥔 신 모듈 |
| `apps/cli.py` | 1,847줄 / 서브커맨드 19개 | |
| `trade/loop.py` | 1,737줄 | |
| 전략이 하는 I/O | `clock.now` 28 · `data.quote` 24 · `data.history` 21 · `broker.positions` 14 | 전략이 세계를 **스스로 당긴다** |
| 전략 가변 상태 | scalp_1m 16 · confluence 13 · intraday_scan 11 (총 ~90) | 숨은 상태 |
| KNOWN_DEBT | 2건 | 평면 규칙은 이미 강제 중 |

**이미 잘 돼 있는 것**: 포트/어댑터(`core/ports.py` ↔ `adapters/`)는 hexagonal
그 자체이고 임포트 그래프로 강제된다. 전략 추가는 파일 1 + 레지스트리 1줄 +
설정 블록 1개면 된다. **배선은 이미 갈아끼우기 쉽다.**

**안 돼 있는 것**: *판단*이 갈아끼우기 어렵다. 전략이 `ctx`로 아무 데나 닿고
숨은 상태를 들고 있어서, 전략 하나를 이해하려면 전체 장비를 띄워야 한다.

## 설계 원칙

1. **순수 코어, 더러운 껍질.** 판단은 순수함수, I/O는 껍질이 한다.
2. **DTO는 경계에만.** 어댑터↔코어 사이에 DTO 계층을 새로 만들지 않는다 —
   도메인 객체(`Position`/`Bar`/`Quote`)를 그대로 쓰는 지금이 낫다. DTO는
   *전략이 보는 세계*(`StrategySnapshot`)와 *리포트가 그리는 대상*(`ReportModel`)
   두 곳에만 둔다.
3. **DDD 전면 도입은 하지 않는다.** 엔티티는 이미 있고(`core/models.py`),
   바운디드 컨텍스트는 이미 4평면이다. 애그리거트·리포지토리·도메인 이벤트는
   1인 운영 엔진에 의식만 늘린다.
4. **모든 단계에서 테스트가 초록이어야 한다.** 실제 돈이 걸린 저장소다.

## Phase A — 전략을 순수함수로

`quant/core/strategy_api.py` (신규, 외부 의존 0):

```python
@dataclass(frozen=True)
class DataNeeds:            # 전략이 "무엇이 필요한지" 선언한다
    bars: tuple[tuple[str, str, int], ...]   # (symbol, interval, count)
    quotes: tuple[str, ...]
    needs_positions: bool

@dataclass(frozen=True)
class StrategySnapshot:     # 전략이 볼 수 있는 세계의 전부
    now: datetime
    market_open: Mapping[str, bool]
    minutes_to_close: Mapping[str, float | None]
    bars: Mapping[tuple[str, str], Any]
    quotes: Mapping[str, Quote]
    lots: Mapping[str, dict]        # 이 전략 몫만
    tags: Mapping[str, tuple[str, ...]]
    risk_multiplier: Mapping[str, float]
    budget_krw: float               # 전략 자기 예산(자본 정책이 결정)

@dataclass(frozen=True)
class Decision:
    signals: tuple[Signal, ...]
    next_state: Mapping[str, Any]   # 껍질이 **체결 확인 후에만** 적용한다
```

```python
class PureStrategy(Protocol):
    id: str
    symbols: list[str]
    def requirements(self) -> DataNeeds: ...
    def decide(self, snap: StrategySnapshot, state: Mapping) -> Decision: ...
```

껍질(`quant/trade/strategy/shell.py`)이 기존 `Strategy` Protocol(`on_cycle(ctx)`)을
만족시키며 `PureStrategy`를 감싼다 — **기존 전략 10종은 한 줄도 안 바뀌고 계속
돈다.** 두 계약이 공존한다.

얻는 것(전부 이번 주 실제 사건):
- `scalp_1m`이 **체결 전에** 플래그를 찍던 문제 → 상태를 반환만 하고 체결 후
  적용하므로 **구조적으로 불가능**해진다.
- `cross_momentum` 8일 무동작(휴장일 게이트 소진) → 휴일 포함 한 주를 상태기계로
  돌리는 테스트로 즉시 발견.
- 일봉 캐던스에서 조건이 영원히 거짓 → 캐던스가 입력이라 표 기반 테스트로 커버.
- 느린 사이클 2.5초·경고 125건 → `requirements()`로 루프가 **한 번에 모아** 받는다.

**못 잡는 것(정직하게)**: 오늘 아침 장부 배선 누락, 저장소 루트 경로 착오, 국면
캐시 낡음 — 전부 조립·운영 결함이라 전략 순수성과 무관하다.

파일럿은 `donchian`(상태 3개) → 검증 후 `scalp_1m`(16개).

## Phase B — 자본 정책 (실전 전환의 다리)

지금은 `per_strategy_initial_krw: 10_000_000` 고정. 이를 **정책**으로 일반화한다:

```yaml
risk:
  capital_mode: per_strategy      # per_strategy | shared
  capital_policy: fixed           # fixed | equal_split
  per_strategy_initial_krw: 10000000   # fixed 에서만 쓴다
```

- `fixed` — 지금(모의): 전략마다 1,000만원. 명목 합계가 실계좌를 넘어도 된다.
- `equal_split` — **실전**: 실제 총현금 ÷ 활성 전략 수. 합계가 실계좌와 정확히
  일치하므로 명목/실제 괴리가 사라지고, 전략별 현금 게이트가 **진짜** 게이트가 된다.

같은 장부·게이트 코드가 모의와 실전 양쪽을 돌린다 — 실전 전환에 새 코드가 필요 없다.

## Phase C — 텔레그램을 전략마다

지금은 전 전략을 한 메시지에 몰아 보낸다. 전략마다 따로 보낸다:

- **요약 1건**: 순위 + 합계
- **전략별 1건씩**: 시작금 → 현금+주식 → 평가/수익률 → 실현·미실현 → 보유 → 거래·승률
- 활동도 보유도 없는 전략은 요약 한 줄로 접는다(10개가 전부 "+0.00%"로 오면
  알림 피로만 는다 — 소유자 지침: "유저가 봤을 때 이해가 안 되면 필요없는 정보").

## Phase D — 리포트를 수집/모델/렌더로 3분할

`apps/report_cli.py`(2,472줄, 임포트 53) → 세 덩어리:

```
quant/report/collect/   섹션별 수집기 — 바깥에서 데이터를 가져온다
quant/report/model.py   ReportModel (순수 DTO) — 리포트가 그릴 대상 전부
quant/report/render/    html / telegram 렌더러 — 모델만 보고 그린다
apps/report_cli.py      얇은 진입점(인자 파싱 + 조립)만 남긴다
```

섹션 하나를 고칠 때 **수집기 하나 또는 렌더러 하나**만 만진다. 렌더 변경이
수집을 깨뜨릴 수 없고, 그 반대도 마찬가지다.

# 보강 — 루프 공학 관점 (2026-08-19 저녁, 소유자 지시)

소유자 정리: *"기존 워크플로우도 결국 loop engineering 이라고 볼 수 있는데, 여기에
이 loop 에 자체점검 타이밍까지 설계하는 것이고, 한국장은 미국과 다르게 주식 갯수
단위로만 구매 가능하다는 것, 그리고 외국인 추세 매매 같은 장기 전략은 타이밍과
근거가 더 중요해진다는 것(단타처럼 단순 숫자가 아니고, 호재 뉴스 이벤트성 투자가
아님). 이것들을 제대로 반영해야 한다."*

## 원칙 1 — 자체점검은 루프의 한 단계다

지금까지 워치독은 루프 **밖에서** 규칙을 훑는 장치였다. 그래서 오늘 하루에만
5건을 놓쳤다(장부 미배선 / KOSPI 역방향 / 매수액 2배 / 문구 오류 / 빈 원장 읽기).
전부 **에러를 내지 않고 그럴듯한 값**을 냈기 때문이다.

자체점검을 루프의 정규 단계로 승격한다:

```
수집 → 분석 → 거래 → 제어 → [자체점검] → 다음 사이클
                                  ↑
                       하루 2회, 정해진 시각에
                       "의도와 실제가 벌어졌는가"를 판단
```

- 점검 시각은 **정보가 가장 많이 쌓였고 아직 손쓸 수 있는 지점**에 둔다:
  KR 은 오후 마감 리포트 **전**, US 는 정규장 중간.
- 규칙(`health.py`)이 잡는 것은 규칙이 잡는다 — 싸고 확실하다.
  판단 레이어는 **규칙이 표현할 수 없는 것**만 맡는다: "값이 임계를 넘었나"가
  아니라 "이 동작이 우리가 의도한 것과 같은가".
- 판정은 **근거 인용 필수**. 근거 없는 경보는 거짓 경보가 되고, 거짓 경보가 오는
  감시는 사람이 꺼버린다.

## 원칙 2 — 한국장은 주 단위다 (시스템 불변식)

**한국 주식은 정수 주 단위로만 살 수 있다. 금액을 겨냥하는 주문이 불가능하다.**
미국은 소수점 매수가 되지만 한국은 안 된다.

이걸 전략마다 각자 근사하게 두면 오늘 같은 사고가 반복된다:
`frgn_accumulate` 가 `target_weight = 100,000원 / 추정자본 500만` 으로 금액을
근사했는데, 전략 자본이 1,000만으로 바뀌자 **매수액이 2배**가 됐다(실측:
001450 4주 200,050원, 의도 100,000원). 아무도 몰랐다.

**따라서 "몇 주를 살 것인가"를 전략이 직접 말할 수 있어야 한다.** 금액을 비중으로
근사하고 그 비중을 다시 수량으로 되돌리는 왕복이 오차의 원천이다.
리스크 레이어의 하드레일(포지션 상한·종목 상한·주문 상한·전략별 현금 게이트)은
그대로 적용된다 — 수량 지정이 레일을 무력화해서는 안 된다.

## 원칙 3 — 장기 전략은 타이밍과 근거가 판단이다

단타는 숫자가 판단이다(돌파했나, 거래량이 몇 배인가). **장기 전략은 다르다.**
외국인 추세 추종은 호재 뉴스에 반응하는 이벤트 매매가 아니라, **수급이 쌓이는
방향에 조금씩 얹는 것**이다. 그래서 두 가지가 숫자보다 중요하다:

**(가) 언제 보는가.** 지금은 태그를 13:55 에 붙이고 전략이 **다음 날 10:00** 에
그 태그를 보고 산다 — 즉 **오늘 외국인이 얼마나 샀는지가 오늘 판단에 전혀 들어가지
않는다.** 하루가 통째로 밀린다.
→ 장 마감 무렵(15:00 전후)에 그날 수급을 보고 판단한다. 그 시각이면 그날 외국인
순매수가 사실상 확정되고, 아직 당일 종가로 살 수 있다.

**(나) 무엇을 근거로 사는가.** 임계값 하나로 자르지 않는다. 두 갈래를 둔다:
- **근거 A — 수급 + 호재**: 그날 외국인 순매수 상위에 있고, 우리 리포트가 그 종목에
  호재를 잡았다. 두 축이 같은 방향을 가리킨다.
- **근거 B — 수급 단독, 단 압도적일 때**: 뉴스에는 없지만 그날 외국인 매수량이
  **그 종목 자신의 최근 이력에 비해** 압도적이다. 남과 비교하는 절대 순위가 아니라
  **자기 자신과 비교하는 상대 강도** — 대형주와 중소형주를 같은 자로 재지 않기 위함.

어느 갈래로 들어갔는지를 **원장에 남긴다.** 나중에 "A 로 산 것과 B 로 산 것 중
무엇이 벌었나"를 채점할 수 있어야 한다 — 이 저장소의 원칙(*숫자가 자본 배분을
결정한다*)을 장기 전략에도 적용하는 유일한 방법이다.

**매수 단위는 1주.** 소유자 실사용 근거: *"어제 삼성전자를 1주 샀고, 오늘 장중
하락했길래 하나 더 샀는데 마감 반등이 나와 자연스럽게 이득을 봤다. 1주씩 하루하루
모으면 장기적으로 좋다."* 금액이 아니라 **횟수와 꾸준함**이 이 전략의 엔진이다.

### 아직 정하지 않은 것 (구현 전 결정 필요)
- 외국인 순매수가 우리가 상정한 적립 속도보다 **훨씬 클 때** 어떻게 대응할지
  (1주 유지 / 그날만 늘리기 / 무시). 소유자 제기, 미결.
- 종목 발굴 범위: 지금은 관심종목에 이미 있는 것만 본다. 외국인 순매수 상위에
  있으나 관심종목에 없는 종목을 편입할지.

## 원칙 3 보강 — 외국인 추종의 근거를 문헌에서 가져온다 (2026-08-19 웹 리서치)

소유자 지시: *"외국인 추종매매를 어떤 식으로 하는 건지 잘 몰라서, 압도적의 기준을
떠나서 실제로 웹서치를 통해 비슷한 추세 추종 매매가 따르는 공식을 따라가자."*

### 반대 증거를 먼저 적는다 — 이게 가장 중요하다

**한국 실증 2건이 "단순 추종은 언더퍼폼"이라고 말한다.**
- 한양대 재무관리연구(2012), 2004~2010 외국인 일별 거래 자료:
  *"외국인에 대한 추종수익률은 KOSPI 수익률이나 CAPM 에 의한 위험조정수익률보다
  **낮게** 산출되었다."*
- LG경제연구원:
  *"외국인이 특정일 순매수 패턴을 취했을 경우 **그 다음 날까지는** 주가 상승세가
  이어졌지만 **이틀째부터는 방향이 일정하지 않아** 개인들의 추종 매수는 높은
  투자성과를 기대하기 어려웠다."*

효과가 **하루짜리**인데 이 전략은 며칠~몇 주를 들고 간다. 지평이 어긋난다.

### 국제 문헌은 예측력을 보고하되 조건이 붙는다
- 순자금유입은 수익률을 양(+)으로 예측하며, 위기 구간 2개월·평시 더 긴 지평까지
  지속(Financial Innovation, Springer 2021).
- 단 예측력이 나오는 형태는 **횡단면 + 이상 보유량(공매도 대비 상대, NAT)**이지
  "어제 순매수액" 자체가 아니다(KAIST).
- **기관 매매는 예측력이 없다** — 외국인만 다르다. 우리가 기관을 노이즈로 본 판단은
  문헌과 일치한다.

### 그래서 채택하는 형태
1. **하루 값보다 누적**(5일·20일). 기존 `foreign_trend.classify()` 의 연속 구간
   판정이 이미 이 방향이다 — 버리지 않는다.
2. **이상치 판정은 고정 배수가 아니라 롤링 z-score.**
   `z = (오늘 순매수 − 최근 N일 평균) / 최근 N일 표준편차`
   소유자 원안("직전 5일 합의 2배")은 직관적이지만 **종목마다 자가 다르다** —
   삼성전자의 2배와 중소형주의 2배는 다른 사건이다. z-score 는 그 규칙을 종목별로
   자동 조정한 형태이고, 실무·문헌의 표준 정규화다(창 길이는 "되돌림 지평에 맞춘다").
3. **shadow 부터.** 한국 실증이 언더퍼폼을 보고하는데 바로 실탄을 넣을 이유가 없다.
   판정을 원장에 남겨 몇 주 뒤 *"우리 데이터에서도 언더퍼폼하는가"* 를 우리 숫자로
   답한다 — 남의 논문이 아니라.
4. 진입 근거를 **A(수급+호재) / B(수급 단독, z-score 이상치)** 로 나눠 원장에 남긴다.
   나중에 "A 로 산 것과 B 로 산 것 중 무엇이 벌었나"를 채점하기 위함이다.
