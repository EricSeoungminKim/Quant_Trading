# 매일 리포트 + 개장일 집계 창 (서브프로젝트 G) — 설계 스펙

> 2026-08-16 사용자 요구. **구현은 B(리포트 고도화) 납품 승인 후.**
> 원문 요지: 리포트를 주말·공휴일 포함 매일 텔레그램으로 보내라. 개장일에는
> "마지막으로 장이 열린 날 ~ 당일" 사이의 뉴스·리포트를 전부 보되, 같은 종목의
> 중복 정보는 **가장 마지막 날 것만** 반영하라. 공휴일은 API 로 확인하지 말고
> 자체 데이터로 판정하라. (실전 케이스: 2026-08-17 월요일 = 광복절 대체공휴일)

## 원칙

1. **매일 증분, 개장일 집계.** 주말이라고 큰 창을 새로 긁는 게 아니라, 매일
   리포트가 그날치를 처리해 두고 개장일 아침 리포트가 사이 기간의 **일별 산출물
   (engine JSON·selections)** 을 집계한다. 부담은 하루치 그대로, 창만 넓어진다.
2. **개장일 판정은 달력이 아니라 데이터.** "마지막 개장일" = 그 시장의 앵커 심볼
   일봉(`data/history/069500/1d`(KR) / `QQQ/1d`(US))이 **마지막으로 새로 생긴 날**.
   일봉은 개장일에만 생기므로 공휴일 API·달력 하드코딩이 불필요하다. 이 저장소의
   기존 원칙(요일·공휴일 하드코딩 금지 — `news_since_for` 주석)의 확장이다.
   - 앵커 일봉 백필이 죽으면? → "마지막 개장일"이 낡아져 창이 넓어질 뿐,
     틀린 좁힘은 없다(안전한 방향 실패). 백필 신선도는 이미 health 가 감시한다.
3. **종목별 최신일 우선 병합.** 개장일 집계 시 같은 종목이 여러 날 등장하면
   **가장 최근 날짜의 판단(점수·뉴스·관계)** 만 남긴다. 낡은 서술이 최신 사실을
   덮지 않게.

## 구성요소 (구현 시 상세화)

| 조각 | 내용 |
|---|---|
| 크론 | 리포트·deepdive·close-report 를 `1-5` → 매일(`*`)로. 뉴스 수집은 이미 매일 |
| 발송 | 리포트 완성 시 텔레그램 요약+링크(스케줄 푸시 갈래, own_brief 패턴) — 매일 |
| 개장일 판정 | `last_open_day(market) -> date` 순수 함수 — 앵커 일봉 파일의 마지막 날짜 |
| 집계 | 개장일 빌드에서 `[last_open+1 .. today]` 의 일별 selections/engine JSON 을 종목별 최신일 우선으로 병합해 후보·요약에 반영 |
| 엔진 | 무변경 — 세션 게이트가 이미 공휴일에 거래하지 않는다(개장 여부는 시세로 판정) |
